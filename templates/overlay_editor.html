Loading a ROM via URL

Pass a direct link to a .rom, .bin, or .zip file as a query parameter. The server proxies the fetch to bypass CORS.

/emulator?rom=https://raw.githubusercontent.com/user/repo/main/game.rom

GitHub tip: use raw.githubusercontent.com — not the blob viewer URL.

Upload & Play

POST a ROM or ZIP to get a 30-minute token, then navigate to the returned play_url.

curl -X POST /emulator/game/upload \
  -F "file=@game.rom"

# → {"play_url": "/emulator?rom_token=uuid",
#     "expires_in": 1800}

Open the play_url in a browser, provide BIOS files, and press Play.

INTV Graphics Primer

                
Everything you need to know to draw your first sprite

                
            


            


                
                

                    
① The Big Picture

                    
The Intellivision uses a chip called the STIC (Standard Television Interface Circuit) to draw graphics. It can display two types of visuals at the same time:

                    

                        

                            
🖼️

                            Background Tiles
                            
A fixed 20 × 12 grid of 8×8 pixel tiles that fills the screen. You place tiles by writing values into a region of memory called the BACKTAB.

                        

                        

                            
👾

                            MOB Sprites
                            
Up to 8 Moving Objects that float freely over the background at any pixel position. MOBs are perfect for players, enemies, and bullets.

                        

                    

                


                
                

                    
② GRAM — Your Art Canvas

                    
GRAM (Graphics RAM) is a bank of 64 custom 8×8 pixel cards, numbered 0 – 63. You draw your pixel art here and then reference these cards from tiles or MOBs. The 64-slot budget grid in the editor shows you exactly which slots you've used.

                    

                        💡 GROM (built-in ROM) holds 64 pre-drawn cards (the Intellivision font). GRAM lets you replace or add your own.
                    

                


                
                

                    
③ Drawing Pixels — BITMAP

                    
In IntyBASIC, each row of pixels is one BITMAP line with 8 characters:

                    
    
                        
  • X — foreground pixel (shows the sprite's color)
    • 
                        
  • . — background pixel (transparent on MOBs; background color on tiles)
    • 
                    

                    


player:
    BITMAP "..XXXX.."   ' row 0 — top of head
    BITMAP ".XXXXXX."   ' row 1
    BITMAP "XX....XX"   ' row 2
    BITMAP "XXXXXXXX"   ' row 3
    BITMAP "XX....XX"   ' row 4
    BITMAP ".XXXXXX."   ' row 5
    BITMAP "..XXXX.."   ' row 6
    BITMAP "........"   ' row 7 — empty

                    

                    
The Sprite Editor generates this code for you automatically. You just draw with your mouse!

                


                
                

                    
④ Loading Art into GRAM — DEFINE

                    
Before the STIC can display your sprite, you must copy it from your program's data into GRAM:

                    


DEFINE slot, numCards, label

DEFINE 0, 1, player     ' copy player into slot 0  (one 8×8 card)
DEFINE 5, 2, tall_guy   ' copy tall_guy into slots 5–6 (two cards = 8×16)
DEFINE 10, 4, boss      ' copy boss into slots 10–13 (four cards = 16×16)

                    

                    
The editor writes the correct DEFINE line for you in the output panel, using the GRAM Slot you assign in the properties panel.

                


                
                

                    
⑤ The 3 Use Modes

                    


                        

                            
MOB Sprite

                            
A hardware sprite that moves freely anywhere on screen. Use the SPRITE command to place it:

                            


SPRITE n, (x + $200), y, (slot * 8 + color)

' Example: MOB 0 at (50,60), slot 2, White
SPRITE 0, (50 + $200), 60, (2 * 8 + 7)

                            

                            
    
                                
  • n — which MOB (0–7)
    • 
                                
  • x + $200 — X position; $200 makes it visible
    • 
                                
  • slot * 8 + color — which GRAM card and which of the 8 primary colors
    • 
                            

                            
One color only. All X pixels show that color; . pixels are transparent.

                        


                        

                            
Color Stack Tile

                            
A background tile placed in the 20×12 grid. Uses a shared "color stack" of up to 4 background colors that advance as tiles are rendered left-to-right, top-to-bottom.

                            


BACKTAB(row, col) = fgColor + slot * 8 + $800

' Slot 3, foreground = Green (5)
BACKTAB(2, 4) = 5 + 3 * 8 + $800

                            

                            
    
                                
  • fgColor — foreground color 0–7 for this tile
    • 
                                
  • $800 — GRAM flag (tells STIC to use GRAM, not GROM)
    • 
                                
  • + $2000 — "Advance" bit: shifts to the next color stack entry
    • 
                            

                            
Best for large colorful backgrounds. Background color comes from the stack, not per-tile.

                        


                        

                            
FG/BG Tile

                            
A background tile where each card can have its own foreground and background color, set via STIC color registers. More flexible than Color Stack but requires more setup.

                            


BACKTAB(row, col) = slot * 8 + $C00

' Set per-row color registers before drawing
' $C00 = GRAM flag ($800) + FG/BG mode flag ($400)

                            

                            
    
                                
  • Foreground: 0–7 (primary colors)
    • 
                                
  • Background: 0–15 (all 16 colors)
    • 
                                
  • Colors are set via STIC register writes, not BACKTAB bits
    • 
                            

                            
Powerful for status bars, score displays, and anything needing exact per-tile coloring.

                        


                    

                


                
                

                    
⑥ Wide & Tall Sprites — Using Multiple Cards

                    

                        

                            
8×8

                            
1 GRAM slot
One DEFINE, one label, 8 rows of BITMAP

                        

                        

                            
8×16

                            
2 GRAM slots
One label, 16 rows of BITMAP.
DEFINE slot, 2, name

                        

                        

                            
16×8

                            
2 GRAM slots
Two side-by-side MOBs.
name_0 left, name_1 right

                        

                        

                            
16×16

                            
4 GRAM slots
Four MOBs in a 2×2 grid.
name_0…name_3

                        

                    

                    
For 16-wide sprites you need multiple SPRITE commands, one per MOB, placed at x and x+8.

⑧ Hello World — Your First Sprite

                    
Here's the minimal IntyBASIC code to put a white box on screen as a MOB:

                    


' 1. Define the BITMAP data
box:
    BITMAP "XXXXXXXX"
    BITMAP "X......X"
    BITMAP "X......X"
    BITMAP "X......X"
    BITMAP "X......X"
    BITMAP "X......X"
    BITMAP "X......X"
    BITMAP "XXXXXXXX"

' 2. Load into GRAM slot 0
DEFINE 0, 1, box

' 3. Place MOB 0 at screen position (50, 50), White (color 7)
SPRITE 0, (50 + $200), 50, (0 * 8 + 7)

' 4. Start the game loop
DO
    WAIT        ' wait for video frame
LOOP

                    

                    

                        ✅ Draw your design in the editor above, copy the generated code from the Output panel, and paste it directly into your IntyBASIC source file.

  1. Choose a size — 8×8 for simple sprites, 8×16 for taller characters, 16×16 for large bosses.
    2. 
                        
  2. Draw your pixel art — Left-click to draw foreground pixels; right-click to erase.
    3. 
                        
  3. Assign a GRAM slot — Enter a slot number in the Sprite Properties panel. Check the GRAM budget grid to avoid conflicts.
    4.

    5. 
                        
  5. Set the color — Choose the MOB color or tile foreground color in the properties panel.
    6. 
                        
  6. Copy the output — Click Copy Bitmap or use the Output panel. Paste into your .bas file.
    7. 
                        
  7. Add more sprites — Use Add in the Sprites panel. Each gets its own GRAM slot automatically.
    8. 
                        
  8. Save your work — Export Project saves a .json file you can reload later.
    9. 
                    

                


                

                    
⑩ Reconstruct Screens from a Live Game

                    
The Sprite Editor and Layout Designer can import memory dumps from jzIntv's debugger to rebuild any screen of any Intellivision game — your own work, a homebrew, or a commercial title.

                    
What you need:

                    
    
                        
  • jzIntv launched with the -d flag (debugger enabled)
    • 
                        
  • Any Intellivision ROM running to the screen you want to capture
    • 
                        
  • Press F4 in the game window to break into the debugger (or Ctrl+C in the terminal)
    • 
                    


                    
Step 1 — Capture GRAM: At the debugger prompt, run m 3800 200. Copy the output (lines starting 3800:), then in the Sprite Editor toolbar click 📥 Paste GRAM and paste. Every non-empty GRAM card becomes an editable 8×8 sprite at its original GRAM slot.


                    
Step 2 — Capture BACKTAB: At the same break point, run m 200 F0. Copy the output. Open 🖥️ Layout View, click 📥 Paste BACKTAB, and paste. The full 20×12 screen reconstructs:

                    
    
                        
  • GRAM tiles render with the pixel art you imported in Step 1
    • 
                        
  • GROM tiles (the Intellivision's built-in character set) show as gray G<n> placeholders so the layout structure is always visible
    • 
                        
  • Per-cell foreground and background colors are decoded for both Color Stack and FG/BG STIC modes
    • 
                    


                    
Tip: take both dumps at the same break point. The GRAM and BACKTAB need to match — if the game animates between dumps, the BACKTAB may reference card numbers that don't exist yet in your imported GRAM.


                    

                        Feature suggested by Steve Ettinger, original Mattel Electronics Intellivision programming team.

INTV Audio Primer

                
Everything you need to know to compose your first Intellivision song

                
            


            


                

                    
① The Sound Chip — AY-3-8914 PSG

                    
The Intellivision uses a Programmable Sound Generator (PSG) chip that provides:

                    
    
                        
  • 3 melody channels — each produces a square wave at a programmable frequency. They're completely independent: different notes, different octaves, different instruments.
    • 
                        
  • 1 noise channel — generates white noise for percussion. IntyBASIC maps drums (M1/M2/M3) to this channel automatically.
    • 
                    

                    
With the ECS expansion, a second PSG is available — doubling you to 8 channels (6 melody + 2 drum). Click + ECS in the channel toolbar to enable it, or load an 8-arg MUSIC song and it auto-detects. The piano-roll grows a second drum strip (top = ECS) and channels 4–6 paint in cyan / yellow-green / tan.

                


                

                    
② The 4 Instruments — W, X, Y, Z

                    
IntyBASIC shapes each note with an envelope — how the volume rises, holds, and fades. The four letters select different shapes:

                    

                        

                            
W — Piano

                            
Sharp attack, quick decay, minimal sustain. Notes are short and percussive. Good for staccato melodies and rhythm accents.

                        

                        

                            
X — Clarinet

                            
Medium attack, strong sustain. The most common melody voice — warm, held, woody. Best for lead lines and counter-melodies.

                        

                        

                            
Y — Flute

                            
Soft attack with gentle vibrato (pitch wobble). Airy and ethereal. Works for atmospheric pads or slow melodic lines.

                        

                        

                            
Z — Bass

                            
Same square wave, but dropped one octave from the written note. Long sustain. Put it on channel 3 and write bass lines — the octave drop gives the low end real weight.

                        

                    

                    
Once you set an instrument on a channel (e.g. C4X), it carries over for all subsequent notes on that channel until you change it.

                


                

                    
③ Drums — M1, M2, M3

                    
The 4th argument of each MUSIC statement controls the noise/percussion channel:

                    
    
                        
  • M1 — Strong: Low-frequency noise burst filtered through a lowpass → a "kick drum" thud. Use on beats 1 and 3.
    • 
                        
  • M2 — Tap: Short high-frequency noise snap → a "snare" click. Use on beats 2 and 4 (backbeat).
    • 
                        
  • M3 — Roll: Medium-frequency shimmering noise → a "hi-hat" sizzle. Use on every tick for a steady rhythm pulse.
    • 
                        
  • - — Silence. No drum this tick.
    • 
                    

                    
A basic rock beat at 16 ticks per bar: M1 M3 M3 M3 | M2 M3 M3 M3 | M1 M3 M3 M3 | M2 M3 M3 M3

                


                

                    
④ Tempo — DATA & Ticks

                    
IntyBASIC's music engine runs at 50 ticks per second (on both NTSC and PAL). The DATA value at the top of your song sets how many ticks each MUSIC line lasts:

                    
    
                        
  • DATA 6 → 50/6 ≈ 8.3 notes/sec → ~125 BPM (fast, driving)
    • 
                        
  • DATA 8 → 50/8 = 6.25 notes/sec → ~94 BPM (moderate)
    • 
                        
  • DATA 10 → 50/10 = 5 notes/sec → ~75 BPM (slow, atmospheric)
    • 
                    

                    
You can change tempo mid-song with MUSIC SPEED <n>.

                


                

                    
⑤ Notes & Octave Range

                    
Notes are written as letter + octave, optionally with # for sharp and an instrument letter:

                    

                        C4   D4#   E3Z   A5X   G2   B4#Y   F4W
                    

                    
The PSG's usable range is C2 (low rumble) to C7 (thin squeak). The sweet spot for melodies is C3–C6. Bass lines with Z instrument work best at C2–C3 (they'll sound an octave lower due to the Z drop).

                    
S (sustain) = hold the previous note. - = silence.

                


                

                    
⑥ Song Structure — Looping

                    
Most Intellivision songs use the intro + loop pattern:

                    
MySong:
  DATA 6
  MUSIC E4X, E2Z, -, M1     ' intro bar
  MUSIC G4X, S,   -, M3
  ...

MySong_loop:
  MUSIC C4X, C3Z, -, M1     ' main body starts here
  MUSIC E4X, S,   -, M3
  ...
  MUSIC JUMP MySong_loop     ' loops back forever

                    
MUSIC JUMP <label> loops back to a label. MUSIC REPEAT loops the entire song. MUSIC STOP ends playback. The Music Studio's 🔁 Loop button plays the loop body multiple times so you can listen continuously.

                


                

                    
⑦ Hardware Hazard — DOSOUND clobbers $011E

                    
Tip from Steve Ettinger, legendary Intellivision developer:

                    

                        If you (or anyone) is using the Exec DOSOUND routine, there is a RAM address ($011E) in user RAM that gets overwritten indiscriminately by the DOSOUND — BEWARE when coding your own game to be SURE that you burn that location with a dummy RAM variable so that your game won't be tanked by DOSOUND!
                    

                    
What this means for you:

                    
    
                        
  • The Music Studio is unaffected. IntyBASIC's MUSIC engine writes the PSG registers directly — it does not route through DOSOUND. Songs exported from this editor are safe.
    • 
                        
  • If your game also uses SOUND statements (which compile down to DOSOUND-style PSG writes), reserve $011E with a dummy variable so the EXEC's sound routine doesn't silently corrupt whatever else you stored there.
    • 
                        
  • Watch out for this if you ever see a variable mysteriously changing during gameplay while sound effects play — $011E is the prime suspect.
    •
